dlt+ では、[キャッシュ](../../core-concepts/cache.md) を操作する Arrow ベースの変換を定義できます。
実際の変換コードは `./transformations` フォルダにあります。
このセクションでは、Python で Arrow ベースの変換を定義する方法を学習します。

## テンプレートを生成

この機能はまだ開発中であり、ドキュメントも限られているため、まずはテンプレートから始めることをお勧めします。
以下のコマンドでテンプレートを生成できます。

:::note
以下のコマンドを実行する前に、`dlt.yml` ファイルで [キャッシュと変換が構成されている](./setup#configure-dltyml-file) ことを確認してください。
:::

```sh
dlt transformation <transformation-name> render-t-layer
```

このコマンドを実行すると、`./transformations` フォルダ内に新しい変換セットが作成されます。生成されるテンプレートには以下が含まれます。

* `dlt_load_id` に基づいて増分ロード状態を管理する変換関数。
* ユーザー定義の変換を実装する 2 つの変換関数。
* 現在の変換実行に適した行のみを事前に選択するステージングビュー。
* 最初はすべての入力行を変更せずに転送するメイン出力テーブル。

生成された変換を変更せずに実行すると、実行は失敗します。
これは、キャッシュが `<transformation-name>` に対応する集計テーブルを期待しているにもかかわらず、新しく作成された変換にそれが含まれないために発生します。この問題を解決するには、次のいずれかを実行できます。

* 新しい変換に合わせてキャッシュ設定を更新する。
* 想定されるテーブル構造に合わせた変換を実装する。

## 増分変換について

scaffolding コマンドによって生成されるデフォルトの変換は、入力データセットの `dlt_load_id` を使用して増分的に実行されます。動作は以下のとおりです。

1. `dlt_loads` テーブルはキャッシュ内で自動的に利用可能になります。
2. 変換レイヤーは、入力データセット内に存在する `load_id` を識別します。
3. まだ処理されていない `load_id`（つまり、`processed_load_ids` テーブルに存在しない）のみを選択します。
4. すべての変換が完了すると、`p​​rocessed_load_ids` テーブルは処理済みの `load_id` で更新されます。
5. キャッシュは、実行ごとに `processed_load_ids` テーブルを出力データセットに保存します。
6. 入力データセットを同期する際、キャッシュは出力データセットから `processed_load_ids` テーブルを再読み込みします（存在する場合）。

このメカニズムにより、実行間でキャッシュが保持されない一時的なマシンでも、増分変換がシームレスに機能できるようになります。
